# 7. Диагностика клиента

[Оглавление](../README.md) · [Границы проверки](08-validation.md)

## Проверяйте этап, а не общее «подключено»

| Симптом | Что проверить |
|---|---|
| Нет relay | DNS, исходящую сеть, dispatch-ответ, ID и семейство HSC |
| Call успешен, TCP не открывается | Адрес/порт из результата call, актуальность channel token и handle |
| Forward принят, но кадров нет | Exchange, secure type, sid, LIVE_START, media info, IDR и декодер |
| Exchange `outer=1006`, `tr=None` | Внешний этап API; состояние ключа/камеры и конфликт клиентов; точный смысл кода не установлен |
| `outer=1000`, вложенный отказ | Читать вложенный код отдельно: это другой этап ошибки |
| JSON не расшифровывается | Порядок подписываемых полей, Base64/raw bytes, sid, key/IV, режим AES и PKCS#7 |
| Медиа есть, изображение повреждено | Границы IOTC, 32-байтный header, offset/block_align/skip, CBC-контекст и ключевой кадр |
| SD возвращает 1104 | Истечение SD-сессии; обработка ошибки до сопоставления request ID |
| SD-list не заканчивается | Порядок slice и flag=0, таймаут, ошибка с id=0 |
| SD-чтение остановилось после начала | Окно frames должно считать аудио и видео |
| SD-файлы сдвинуты на часы | Unix seconds против milliseconds, UTC и повторная прибавка локального смещения |
| Нет звука или он искажён | aattr, codec=100/101, отдельный ADPCM predictor/index каждого пакета, частоту и порядок nibble |
| Карта определена, новых файлов нет | SD status, режим/audio/loop, format state и изменение занятого объёма |

Внешние коды 1003/1006 не доказывают автоматически неверный пароль или
неисправность SD. Сначала сохраните внешний и вложенный коды раздельно.

## Что логировать

Фиксируйте текущий этап, время попытки, command/method/request ID, код ответа,
число/размер пакетов, время последнего полного кадра и результат декодера.
Разделяйте последний сбой и текущее состояние: старая ошибка в журнале не
означает, что поток сейчас не работает.

Не помещайте в публичный issue токены, пароли, приватный/shared key,
channel token, QR, полный device-list или необезличенную запись.
Модель, прошивка, ОС, версия декодера и минимальный обмен с заменёнными
секретами обычно полезнее полного дампа аккаунта.

## Переподключение

Различайте обрыв TCP, отсутствие новых полных пакетов и остановку декодера.
Используйте конечные таймауты и backoff с верхней границей; не выполняйте
повторный вход аккаунта каждую секунду. При переподключении проверьте
актуальность токена/публичного ключа, выполните нужный exchange и заново
получите relay-канал. Не продолжайте расшифрование новым ключом в старом контексте.

Интервалы 4 секунды keepalive и около 0,5 секунды PTZ STOP взяты из
рассмотренной реализации. Они не задают SLA восстановления после загрузки
камеры или регистрации в мобильной сети.

## Проверка уже созданного контейнера

Если ваш клиент сохранил MP4 с правильными временными метками:

```sh
ffprobe -v error -show_entries stream=codec_name,codec_type,width,height,duration:format=duration -of json recording.mp4
ffmpeg -v error -xerror -i recording.mp4 -t 10 -f null -
```

Вторая команда проверяет только первые 10 секунд. Для полного декодирования
уберите `-t 10`. Наличие AAC-дорожки не доказывает, что в сцене был слышимый звук.
Файл с расширением `.mp4`, в который просто записан elementary stream, контейнером не становится.

## Неустановленные части

Полный смысл QR-полей, всех ошибок API, всех DPID/mode/filter, единиц SD capacity,
семантики `exp` и региональных различий не установлен. Наблюдавшиеся значения
нужно перепроверять для других прошивок. Не назначайте неизвестному полю
новое значение методом догадки на рабочей камере.
